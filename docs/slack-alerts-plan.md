# 계획: WBS 슬랙 알림

작성: 2026-08-23  
상태: **미구현. 아래 권장안 확인 후 구현.**  
대상: Sevensplit WBS Dashboard (`sevensplit-wbs-dashboard`)

이 문서는 구현 전에 범위·데이터·권한·스케줄을 고정하기 위한 계획이다. 비밀값(웹훅 URL, 토큰)은 적지 않는다.

---

## 1. 목표

평일 기준으로 아래 두 가지를 슬랙으로 알린다.

| # | 언제 | 누구에게 | 안내 |
|---|---|---|---|
| 1 | 리프 작업에 **담당자가 없음** (일정 없음도 같은 묶음에 포함) | 그 작업이 속한 **프로젝트 PM** | 담당자와 일정을 넣으라는 안내 |
| 2 | **종료일(없으면 시작일)이 오늘보다 과거**인데 진척이 100% 미만 | 그 작업의 **담당자** | 완료 처리 **또는** 일정승인을 **지연**으로 바꾸고, 지연 사유·새 일정을 노션에 반영하라는 안내 |

PM과 슬랙 URL은 **슈퍼관리자**가 권한 화면에서 가입자에게 붙인다. 앱이 노션을 직접 고치지는 않는다(1차는 알림만).

---

## 2. 지금 코드와의 간격

이미 있는 것:

- 노션 WBS를 서버에서만 읽음. 리프·담당자·일정·진척·일정승인·서비스·상위 제목 경로.
- Firestore `users/{uid}`: 이메일, 표시 이름, `workName`, 페이지 ACL. 슈퍼관리자만 목록·ACL 수정.
- 일정승인 값: **미지정 · 승인 · 반려 · 보류**. **지연은 없음.**
- 기한초과는 이미 `taskStatus`: 종료일(없으면 시작일) `<` 오늘(KST) 이고 미완료.
- 담당자 매칭은 프로필 `workName`과 노션 이름 **완전 일치**.
- `firebase-admin` 없음. Firestore는 **사용자 ID 토큰 REST**. CD 서비스 계정은 GitHub Actions에 있음.

없는 것:

- PM, 슬랙 URL, 알림 로그, 스케줄러, 일정승인 `지연`, 지연 사유 필드.

제약 (바꾸지 않음):

- `firebase-admin` 다시 넣지 않음. Hosting 쿠키는 `wbs_token`. CD에서 `--only auth` 금지.

## 3. 확인이 필요한 결정 (권장안)

구현 전에 이 표만 맞으면 된다.

| 항목 | 권장 | 다른 안 |
|---|---|---|
| **프로젝트** | 노션 **서비스** 값(하위가 비면 상위 상속). 서비스 없으면 `(서비스없음)` | 트리 **루트 작업명** (`ancestorTitles[0]`) |
| **미지정 알림 대상** | **리프**이고 담당자 배열이 비어 있음 | 상위 행 자체에 담당자가 없는 경우까지 |
| **일정 없음** | 미지정 알림에 **같이** 넣음 (담당 없음·일정 없음) | 일정 없음은 별도 문구 |
| **기한** | `end`, 없으면 `start`. 둘 다 없으면 기한초과 알림 없음 (PM 쪽으로) | 시작일만 보기 |
| **완료** | 진척 ≥ 100% | 일정승인=승인만 완료로 보기 (부하 정의와 어긋남) |
| **이미 지연** | 날짜가 아직 과거면 **다시** 알림 (일정 변경 요청). 날짜가 오늘 이후면 중단 | 지연이면 무조건 중단 |
| **여러 담당자** | `workName`이 맞는 **전원**에게 동일 요약 | 첫 담당자만 |
| **슬랙 URL** | 가입자별 **Incoming Webhook** (또는 워크플로 웹훅) HTTPS URL. 그 URL이 묶인 채널로 감 | 봇 토큰 + Slack 사용자 ID로 DM (별도 Slack 앱, 범위 큼) |
| **PM 할당** | 슈퍼관리자가 **서비스 → 가입자 1명**. 한 사람이 여러 서비스 PM 가능 | 가입자 플래그 `isPm` 하나(전사 1명) |
| **주기** | 평일 **09:00 KST** 1회 + 권한 화면 **지금 보내기** | 매일 포함 주말 |
| **묶음** | 수신자당 **하루 1통** (목록) | 작업마다 1통 |
| **노션 쓰기** | 1차는 **안 함**. 슬랙에 노션 링크 | 대시보드에서 일정승인 패치 (노션 통합 권한·충돌 처리 필요) |

## 4. 개념

```
노션 리프 작업
  ├─ 서비스 ──► projectPms/{serviceKey}.pmUid ──► users/{uid}.slackWebhookUrl ──► PM 알림
  └─ 담당자 이름 ──► users.workName 완전 일치 ──► 그 사용자의 slackWebhookUrl ──► 담당자 알림
```

- **리프:** 하위 항목 relation 0건. 부하·내 업무와 같음.
- **프로젝트:** 권장안은 `task.service`(하위가 비면 상위 트리 서비스 상속). PM 매핑 키는 trim한 서비스명.
- **가입자:** 한 번이라도 로그인한 `@sevensplit.com`. 목록에 없는 사람에게 PM·웹훅을 줄 수 없음.
- **업무 이름:** 본인이 `/profile`에 넣는 노션 담당자 이름. 슬랙 수신자를 찾으려면 필수.

## 5. 데이터

### 5.1 Firestore `users/{uid}`에 슈퍼관리자만 넣는 필드

| 필드 | 형 | 설명 |
|---|---|---|
| `slackWebhookUrl` | string, optional | Incoming Webhook 등 HTTPS URL. 하트비트가 **덮지 않음**. 최대 ~500자 |

본인 PATCH(`/api/me`)와 하트비트 마스크에 넣지 않는다. `workName`과 같은 함정.

### 5.2 Firestore `projectPms/{serviceKey}`

| 필드 | 형 | 설명 |
|---|---|---|
| `service` | string | 노션 서비스 표시명 |
| `pmUid` | string | `users` 문서 ID |
| `updatedAt` | string ISO | |
| `updatedBy` | string | 슈퍼관리자 이메일 |

키: 서비스명을 Firestore 문서 ID로 쓰기 어렵면 SHA-256 hex 또는 URL-safe. 문서 필드에 원문을 남긴다.

한 서비스에 PM **1명**. 비우면 그 서비스 미지정 알림은 슈퍼관리자 요약(또는 스킵)으로 간다.

### 5.3 Firestore `alertLogs/{id}`

같은 날 같은 수신자에게 같은 종류를 두 번 보내지 않기 위함.

| 필드 | 형 |
|---|---|
| `kind` | `unassigned` \| `overdue` |
| `recipientUid` | string |
| `dateKst` | `YYYY-MM-DD` |
| `taskIds` | string[] |
| `sentAt` | ISO |
| `ok` | bool |
| `error` | string, optional |

문서 ID 예: `{kind}_{recipientUid}_{dateKst}`.

웹훅 URL은 로그에 **쓰지 않음**.

### 5.4 노션 (사람이 콘솔에서)

| 속성 | 지금 | 필요 |
|---|---|---|
| 일정승인 | 미지정·승인·반려·보류 | **지연** 옵션 추가 |
| 지연사유 | 없음 | **추가** 권장. rich_text. 앱은 1차에 읽기만 |

앱 `scheduleApproval.ts`에 `지연` 버킷을 넣는다. 일정승인 페이지 다섯 번째 칸.

## 6. 권한·비밀

- 슬랙 URL·PM 지정: **슈퍼관리자만** 쓰기. 가입자는 자기 웹훅을 고치지 않음.
- GET `/api/acl`: 슈퍼관리자에게 웹훅은 **마스킹** (`…` + 끝 8자). 전체 URL은 저장 시에만 보냄.
- Firestore rules: `slackWebhookUrl` optional string, https, size 제한. `projectPms`·`alertLogs`는 슈퍼관리자만 클라이언트에서 읽기/쓰기. 크론이 서비스 계정 REST를 쓰면 rules를 우회하므로 스크립트는 읽기 + `alertLogs` 쓰기만.
- 웹훅은 시크릿이다. git, 채팅, 볼트, 서버 로그에 넣지 않음.
- 알림 API를 둘 경우 헤더 `x-alerts-secret`. GitHub Actions Secret. 쿼리스트링 금지.
- `firebase-admin` 금지. 크론은 **이미 있는** `FIREBASE_SERVICE_ACCOUNT`로 Firestore REST + 노션 토큰.

하트비트(기존 사용자) 마스크는 계속 `displayName`, `lastSeenAt`만.

## 7. 알림 규칙

공통 필터: **리프만**. 상위 행은 보내지 않음.

### 7.1 미지정 → PM

포함:

- `assignees.length === 0`
- 또는 시작·종료가 둘 다 없음 (같은 다이제스트, 사유만 구분)

묶음: `service` → PM uid → 그 사용자 웹훅 1통.

본문에 작업마다: 상위 경로, 제목, 노션 URL, 빠진 것(담당/일정).

PM 없음 / PM `workName` 무관 / 웹훅 없음: 보내지 않고 실행 결과에 `undelivered`로 남김.

### 7.2 기한초과 → 담당자

포함:

- 진척 < 100%
- `end ?? start` 가 있고, 그 날짜 `<` 오늘 KST
- 담당자 1명 이상

제외:

- 완료
- 날짜 없음 (7.1로)

일정승인이 이미 `지연`이어도, 종료일이 과거면 보낸다. 문구만 “일정이 아직 과거입니다”로 바꾼다. 종료일을 오늘 이후로 바꾸거나 완료하면 다음날부터 안 보냄.

담당자 이름 → `workName` 완전 일치 → 웹훅. 매칭 실패는 `undelivered`.

### 7.3 하루 1통

수신자+종류+날짜가 `alertLogs`에 성공으로 있으면 스킵. 실패만 재시도.

## 8. 메시지 초안

채널 Incoming Webhook이면 `@사람` 멘션은 웹훅만으로는 불안정하다. 개인 웹훅이면 그 채널 자체가 수신함.

### PM (미지정)

```
[WBS] 담당자·일정이 비어 있는 작업이 n건입니다.

서비스: {서비스}
대시보드: https://sevensplit-wbs-dashboard.web.app

• {상위경로} / {제목}
  비어 있음: 담당자, 일정
  {노션 URL}

노션에서 담당자와 일정을 넣어 주세요.
```

### 담당자 (기한초과)

```
[WBS] 기한이 지난 미완료 작업이 n건입니다.

• {상위경로} / {제목}
  기한: {end} · 진척: {pct}% · 일정승인: {값}
  {노션 URL}

다음 중 하나로 맞춰 주세요.
1) 작업을 완료(진척 100%)로 표시
2) 일정승인을 "지연"으로 바꾸고, 지연 사유를 적고, 일정을 새 기한으로 수정
```

## 9. 실행 위치

Hosting만 있는 지금 구조에서는 **GitHub Actions 스케줄이 가장 안전**하다. 사용자 Firebase ID 토큰 없이 가입자 목록을 읽어야 하기 때문이다.

```
평일 00:00 UTC (09:00 KST)
  GitHub Actions
    → 노션 query (NOTION_TOKEN)
    → Firestore REST users + projectPms + alertLogs (FIREBASE_SERVICE_ACCOUNT)
    → 규칙으로 다이제스트 작성
    → 수신자별 Incoming Webhook POST
    → alertLogs 기록
```

권한 화면 **지금 보내기 / 미리보기**:

- 슈퍼관리자 세션으로 `POST /api/alerts/run` `{ dryRun?: boolean }`
- Firestore는 그 사용자 ID 토큰으로 list (rules가 슈퍼관리자 list 허용)
- 노션은 서버 `NOTION_TOKEN`
- `dryRun: true`면 웹훅을 치지 않고 수신자·건수만 반환

공유 로직은 `lib/alerts.ts` 한곳. 스크립트와 Route가 같이 쓴다.

주말·공휴일은 1차에서 평일만. 공휴일 캘린더는 넣지 않음.

## 10. 슈퍼관리자 UI (`/admin/access`)

가입자 표에 추가:

- 슬랙 URL: 입력(비밀번호형) + 마스킹 표시. 빈 저장은 “지우기”를 따로.
- 업무 이름은 읽기 전용(본인 프로필 값). 매칭 안 되면 경고 점.

그 아래 **서비스 PM** 표:

- 행: 최근 WBS에서 본 서비스 목록 (+ 수동 추가)
- 열: 서비스, PM(가입자 드롭다운), 웹훅 유무

버튼: 알림 미리보기, 지금 보내기.

미리보기: 미지정 n건 / 기한초과 n건 / 웹훅 없음 / PM 없음.

## 11. 앱 쪽 작은 변경 (알림과 함께)

- `scheduleApproval`: `지연` 추가. `/approval` 필터·배지.
- 기한초과 목록은 기존 `taskStatus === "기한초과"`.
- 검색·내 업무는 그대로. 알림이 화면 필터를 바꾸지 않음.

노션 페이지를 앱에서 PATCH하지 않음. 담당자가 노션에서 고친 뒤 다음 동기화·다음 알림 주기에 반영.

## 12. 구현 순서

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 0 | 이 계획의 표(§3) 확정. 노션에 `지연`, `지연사유` 추가 | 스키마 스크린샷·동의 |
| 1 | Firestore 필드·rules·하트비트 마스크. 권한 UI에 웹훅·PM | 슈퍼관리자가 저장·마스킹 확인 |

| 4 | GitHub Actions `alerts.yml` cron | 평일 09:00 KST 워크플로 초록 |
| 5 | `/approval`에 지연 버킷 | 노션에서 지연 고르면 화면에 보임 |

## 13. 실패·운영

- 웹훅 4xx/5xx: 그 수신자만 실패 기록. 다른 사람은 계속.
- 노션 실패: 전체 중단, Actions 실패. 알림 없음.
- 전달 못 함(PM 없음, workName 없음, 웹훅 없음): dryRun/로그 카운트. 슬랙으로 슈퍼관리자에게 따로 보내지 않음(1차). 필요하면 슈퍼관리자 웹훅 하나를 fallback으로 추가 가능.
- 슬랙 3초 타임아웃·재시도 1회.
- Incoming Webhook은 채널에 묶인다. 사람별 DM이 필요하면 2차에 봇 토큰 + Slack user id.

## 14. 구현하지 않는 것 (1차)

- 노션 페이지 업데이트
- 슬랙 OAuth, 봇 DM
- 공휴일 스킵
- 성과 페이지 알림
- 가입자가 자기 웹훅 수정
- `firebase-admin`, `__session`, `--only auth`

## 15. 구현 시작 전에 답해 줄 것

1. 프로젝트 = **서비스** 맞는지, 아니면 트리 루트인지.
2. 슬랙 URL = 사람별 Incoming Webhook 맞는지 (채널로 감).
3. 평일 09:00 KST 한 번 + 미리보기/지금 보내기 맞는지.
4. 노션 일정승인에 **지연**, 속성 **지연사유**를 추가할 수 있는지.
5. 1차는 노션을 앱이 고치지 않고 안내만 해도 되는지.
